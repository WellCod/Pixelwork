# Pingpong Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Minigame de pingpong na mesa de jogos: solo contra bot ou 1x1, partida simulada pelo servidor a 30 Hz, janela de jogo no cliente e placar sobre a mesa.

**Architecture:** Física e bot num módulo puro em `shared` (`pong.ts`); o mapa compilado ganha as mesas interativas; o servidor mantém um `GameRegistry` por coworking que avança cada partida com o `Scheduler` injetado e conversa pelo WebSocket (mensagens `game.*` e `table.state`); o cliente prevê a própria raquete, extrapola a bola e desenha num `<canvas>` 2D dentro de um modal React.

**Tech Stack:** TypeScript estrito, Zod, Fastify + `ws`, Phaser 4 (só a plaquinha), React, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-22-pingpong-design.md` (decisões de contrato também em `docs/architecture.md`, seção "Interações com objetos").

## Global Constraints

- Servidor com autoridade: o cliente manda só intenção da raquete (`dir: -1 | 0 | 1`), nunca posição (invariante 1).
- Partida é efêmera: só WebSocket, nada no banco (invariante 2); fora do replay determinístico.
- `pong.ts` é puro: estado + entradas + tempo → novo estado + eventos; relógio injetado (invariante 5).
- Código referencia a mesa pelo `item_id` do catálogo (`ping-pong`), nunca por frame ou caminho (invariante 6).
- Nenhuma sala de mídia nova; nenhum intervalo do servidor existe sem partida em andamento.
- Campo 160x90; raquete 3x18 (centro em y), esquerda em x=6..9, direita em x=151..154; bola 3x3 (centro).
- Raquete 120 u/s; bola sai a 80 u/s, +6% por rebatida, teto 200 u/s; ângulo de volta até 60°.
- Quadro de 1000/30 ms; contagem de 3 000 ms antes de cada saque; vence quem fizer 7.
- Tolerância de reconexão = `RECONNECT_GRACE_MS` existente.
- Comandos: `npx -y pnpm@11.20.0 <script>`; testes do servidor precisam do Postgres do `docker-compose.dev.yml`.

## Review Focus

- Bola a 200 u/s atravessando a raquete entre dois quadros (6,7 u por quadro > 3 u de raquete): deve rebater. Teste na Task 1.
- Jogador que já está numa mesa manda `game.join` de novo (mesma ou outra mesa): sai da anterior antes; nunca fica em duas. Teste na Task 4.
- `game.input` de quem não está jogando, ou com `dir` fora de -1/0/1: ignorado sem afetar a partida. Testes nas Tasks 3 e 4.
- Os dois jogadores caem, ou alguém sai durante a contagem: nenhum intervalo sobra e a mesa volta a `free`. Teste na Task 5.
- Troca de mapa que remove ou mantém a mesa: partidas encerram, clientes fecham a janela. Testes nas Tasks 5 e 6.

**Interfaces:**
- Produces:
  ```ts
  export type PongSide = 'left' | 'right';
  export type PongDir = -1 | 0 | 1;
  export type PongPhase = 'countdown' | 'playing' | 'paused' | 'ended';
  export interface PongState {
    phase: PongPhase;
    at: number;              // momento do último passo (ms)
    serveAt: number;         // fim da contagem (ms)
    ball: { x: number; y: number; vx: number; vy: number };
    paddles: { left: number; right: number };   // centro em y
    score: { left: number; right: number };
    servingSide: PongSide;
    firstLoser: PongSide | null;
  }
  export type PongEvent =
    | { type: 'hit'; side: PongSide } | { type: 'wall' }
    | { type: 'point'; side: PongSide } | { type: 'end'; winner: PongSide };
  export const PONG = { W: 160, H: 90, PADDLE_H: 18, PADDLE_W: 3, LEFT_X: 6, RIGHT_X: 151, BALL: 3,
    PADDLE_SPEED: 120, BALL_SPEED: 80, BALL_MAX: 200, SPEEDUP: 1.06, MAX_ANGLE_DEG: 60,
    FRAME_MS: 1000 / 30, COUNTDOWN_MS: 3000, WIN: 7 } as const;
  export function newPong(now: number): PongState;
  export function stepPong(state: PongState, inputs: { left: PongDir; right: PongDir }, now: number): { state: PongState; events: PongEvent[] };
  export function pausePong(state: PongState): PongState;           // phase 'paused'
  export function resumePong(state: PongState, now: number): PongState; // 'countdown', serveAt = now + 3000, bola no centro
  export function botInput(state: PongState, side: PongSide): PongDir;
  ```

Regras que o teste e a assinatura não determinam:
- `dt = min(now - state.at, 100)`; raquetes movem `dir * 120 * dt/1000`, presas a `[9, 81]`.
- Em `countdown`, só raquetes mexem; ao chegar `serveAt`, a bola sai do centro (80, 45) a 80 u/s para o lado oposto a `servingSide`, com ângulo ±20° alternando pela paridade de `left + right`.
- Colisão com a raquete por varredura: se, no passo, a borda da bola cruzou o plano da face (x=9 na esquerda, x=151 na direita) e o y interpolado no cruzamento está a até `9 + 1,5` do centro da raquete, rebate: `rel = clamp((yCruz - paddle) / 10.5, -1, 1)`, ângulo `rel * 60°`, velocidade `min(200, v * 1.06)`, bola recolocada encostada na face.
- Parede: reflete `vy` em y=1,5 e y=88,5 (evento `wall`).
- Ponto quando o centro da bola passa de x<0 (ponto da direita) ou x>160 (ponto da esquerda); grava `firstLoser` no primeiro ponto; depois de cada ponto, `servingSide = floor((total-1)/2) % 2 === 0 ? firstLoser : outro`, nova contagem. Quem chega a 7 → `ended` + evento `end`.
- `newPong`: `servingSide: 'left'`, contagem até `now + 3000`, raquetes em 45.
- `botInput`: se `ball.vx` vai na direção do lado do bot, alvo = `ball.y`, senão 45; devolve 0 se `|alvo - raquete| <= 6`, senão o sinal.

- [ ] **Step 1: Testes que falham** em `pong.test.ts`:
  - `'contagem segura a bola e solta no serveAt'`: em `newPong(0)`, `stepPong(..., 2900)` deixa a bola em (80,45) e `phase 'countdown'`; após 3000 → `phase 'playing'` e `ball.vx > 0`.
  - `'raquete anda 120 u/s e para nas bordas'`: input `left: 1` por 1000 ms em passos de 1000/30 → `paddles.left` = 81 (preso).
  - `'rebate no meio volta reta e acelera 6%'`: bola em x=12, y=45, vx=-80, raquete em 45 → após passo, `vx ≈ 84.8`, `vy ≈ 0`, evento `hit`.

- Produces:
  ```ts
  export interface GameHost {
    clock: Clock; scheduler: Scheduler;
    send(userId: string, msg: ServerMsg): void;
    broadcast(msg: ServerMsg): void;
    activityChanged(userId: string): void;   // runtime chama refresh()
  }
  export type JoinError = 'table_not_found' | 'table_not_at_side' | 'table_side_taken' | 'table_busy';
  export class GameRegistry {
    constructor(tables: CompiledTable[], host: GameHost);
    join(userId: string, tableKey: string, pos: { x: number; y: number }, inCall: boolean): JoinError | null;
    bot(userId: string): void;
    input(userId: string, seq: number, dir: PongDir): void;
    rematch(userId: string): void;
    leave(userId: string): void;            // fechar a janela ou saída definitiva
    seatOf(userId: string): GameSeat | null; // inclui 'waiting'
    states(): TableState[];
    activeMatches(): number;
  }
  ```
- Uma partida guarda `{ state: PongState, left/right: userId | 'bot', inputs, lastSeq por jogador, timer }`. Timer: `scheduler.setInterval(frame, PONG.FRAME_MS)` criado ao começar e cancelado ao terminar/pausar. Cada quadro: `stepPong`, `game.state` para os humanos (com o `ack` de cada um), `game.events` se houver, `table.state` a todos quando o placar ou a fase mudam.
- `join` com o jogador já sentado em alguma mesa: `leave` da anterior primeiro. Segundo humano chegando ao lado livre de uma partida contra o bot: a partida recomeça 1x1 com `newPong(now)`.
- Desistência em 1x1: `game.events` com `end` para quem fica, mesa volta a `waiting` com ele.
- Runtime: `move` de quem tem `seatOf` é descartado (confirmado no `ack`, sem andar); `activityOf` devolve `'game'` depois de `'call'` e antes de `'meeting'`; erros vão como `{ t: 'error', code }`.
